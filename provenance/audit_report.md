## Outcome and scope

The corrected implementation is on branch `revision/fix-leakage-provenance`. Historical result files were not rewritten. The current source fingerprint for the audited implementation is `7f1a85210f1c3dd43c59381cad891e291242d874886f283b1e2b95d02abc84a7`.

The six local historical ledgers/tables checked in `original_run.json` still match their recorded byte counts and SHA-256 hashes. The primary `results_stream.jsonl` has 560,002 rows. The manuscript's 538,972-row number is a historical reported subset count, not a corrected count. `reports/cache.db` was absent. I downloaded and inspected all 25 configured datasets into git-ignored `data/raw/`; 24 are from OpenML and Dry Bean is from UCI. All 25 CSV hashes and sidecar schemas match. Since the historical raw CSV and source metadata are absent, the old run's exact Dry Bean input cannot be independently verified. Its historical result rows remain untouched and must not be relabeled based on the current downloader defect.

The pass covered the runner, splitters, both preprocessing paths, feature generation/selection, shift generation, loader, checkpointing, evaluation, table/statistics/plotting code, entry points, progress utility, notebooks, paper package, config, and archived outputs. The corrected run path is the runner and explicit-path analysis commands in the root README. Legacy analysis code is identified below and must not be used as corrected evidence.

## Primary and segregated conditions

Primary: clean; Gaussian noise at 0.01, 0.05, 0.10; missing values at 0.05, 0.10, 0.20; label noise at 0.05, 0.10, 0.20. The unchanged held-out partition means these estimate performance under training-data corruption, not deployment-time distribution shift.

Segregated: target-free but transductive PCA covariate partitions and K-means population partitions; feature-availability ablation; majority-label relabeling. A run cannot mix these families with the primary family. Domain partition rules use held-out features and are identified as such in manifests.

## Remaining risks and historical status

- The schema screen found no exact target copies or single-feature deterministic target mappings, but cannot rule out semantically derived proxies. `Titanic.name` is a high-cardinality text field for source-level review. The name-only `Google_Index` warning is a likely heuristic false positive, not a proven identifier.
- Many datasets contain repeated feature vectors. The saved audit quantifies them and simulates their overlap under the current row-level five-fold seed-42 splitter. The main exposure is PhishingWebsites and KDDCup99 (roughly two-thirds of test rows have an identical `X` in training). These folds are still disjoint by row index, but not by feature-vector identity; this can make scores optimistic. Group-aware evaluation is not implemented, and no full benchmark was run on these data.
- Three datasets have constant features in the saved data: `ionosphere.a02`, `mushroom.veil-type`, and three KDDCup99 fields. The downloader does not remove them. APS Failure and Titanic have substantial feature missingness, which should remain part of the preprocessing audit.
- PCA/K-means domain partitions remain transductive because all `X` rows determine geometry. They are segregated but do not represent an unseen-domain or training-only corruption evaluation.
- Pipeline selection and comparison reuse the same outer folds. This is not nested cross-validation; choosing a winning pipeline from those results can be optimistic.
- Legacy analysis utilities and the visualization notebook are not corrected analysis paths and retain schema, estimand, or claim issues documented above.
- The historical manuscript methods/results, PDF figures, highlights, and cover letter were not changed or recompiled. Corrected figures/captions and numerical claims must wait for the full corrected benchmark and dataset-level analysis.
- The manuscript currently describes all 25 datasets as OpenML data and says licensing/provenance comes from OpenML records. The verified configuration is 24 OpenML datasets plus UCI Dry Bean; update these methods/source statements when revising the manuscript, after the data and split protocol are finalized.
- The original ledger is available locally and its six recorded artifact hashes still match. Its 560,002 rows and the manuscript's historical 538,972-row subset do not represent corrected results. The original checkpoint DB was unavailable. Therefore corrected manuscript estimates cannot yet be recomputed.
